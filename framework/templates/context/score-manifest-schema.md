# Score Manifest Schema

The `_score_manifest.json` file configures the health score evaluator for a specific project. Generated by an agent during bootstrap or context-refresh. Read by `context-health-score.sh`.

## Location

`.claude/context/_score_manifest.json` (project-level, committed to git)

## Schema

```json
{
  "version": 1,
  "generated_at": "ISO-8601 timestamp",
  "structure_hash": "md5 of directory listing — for stale detection",
  "project_type": "python_fastapi | node_express | go_gin | ...",
  "language": {
    "primary": "python | typescript | go | java | ...",
    "file_extensions": [".py"],
    "function_patterns": ["def %s", "async def %s"],
    "class_patterns": ["class %s"]
  },
  "domains": [
    {
      "name": "human-readable domain name",
      "paths": ["glob patterns matching this domain"],
      "category": "source | infrastructure | config",
      "file_count": 42,
      "freshness_threshold_days": 7,
      "sub_domains": [
        {
          "name": "sub-domain name",
          "paths": ["glob patterns"],
          "file_count": 13
        }
      ]
    }
  ],
  "accuracy": {
    "skip_sections": ["## Provenance", "## Limitations"],
    "search_scope": "domain"
  },
  "completeness": {
    "require_summary": true,
    "require_provenance": true,
    "require_limitations_in_rules": true,
    "require_evidence_in_adrs": true
  }
}
```

## Field Definitions

### `structure_hash`
MD5 of sorted top-level directory listing with file counts. Used to detect when the project structure has changed since the manifest was generated. Computed as:
```bash
find . -type f \( -name "*.py" -o ... \) -not -path "*/..." | sed 's|^\./||' | cut -d'/' -f1 | sort | uniq -c | sort | md5
```

### `domains[].category`
- `source`: Business logic that needs context documentation (coverage scored)
- `infrastructure`: Tests, migrations, scripts, CI config (excluded from coverage)
- `config`: Configuration files, env templates (excluded from coverage)

### `domains[].freshness_threshold_days`
How many days after source code modification before the context file is considered stale. Set by the manifest generator based on recent git activity:
- High-churn domains (10+ commits in 30 days): 7 days
- Medium-churn (3-9 commits in 30 days): 14 days
- Low-churn (0-2 commits in 30 days): 30 days

### `language.function_patterns` / `language.class_patterns`
Printf-style patterns where `%s` is replaced with the identifier name. Used by the accuracy checker to grep for function/class definitions.

### `accuracy.skip_sections`
Markdown heading patterns to skip when extracting verifiable references. Content in these sections is meta-content (provenance dates, acknowledged gaps) not code assertions.

### `accuracy.search_scope`
- `domain`: Search for references only within the domain's directory (faster, fewer false positives)
- `project`: Search the entire project (slower, catches cross-domain references)

## Generation

The manifest is generated by a haiku agent that:
1. Runs `find` to discover directory structure and file counts
2. Detects project type from package manager files
3. Classifies directories by category
4. Checks git activity per directory for freshness thresholds
5. Detects language patterns from file contents
6. Computes the structure hash
7. Writes the JSON file
