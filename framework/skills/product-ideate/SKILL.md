# Ideation Analysis

## Instructions

1. Ask the user to describe their idea in their own words (if not already provided)
2. Structure the analysis using this framework:

### Problem Validation
- What specific problem does this solve?
- Who has this problem? How many of them?
- How painful is it? (Painkiller vs. vitamin)
- How do they solve it today?

### Solution Fit
- How does the proposed solution address the problem?
- What's the core insight or unfair advantage?
- What needs to be true for this to work? (Key assumptions)

### Market Quick-Check
- Use WebSearch to identify: existing competitors, market size signals, relevant trends
- What's the competitive gap? Why hasn't someone done this already?
- Is this a growing or shrinking market?

### Feasibility Gut-Check
- Can this be built as an MVP in 2-4 weeks?
- What's the hardest technical challenge?
- What's the go-to-market path? (How do users find this?)

### Verdict
- **Go / Pivot / Kill** with clear reasoning
- If Go: recommended next step (write PRD)
- If Pivot: what to change and why
- If Kill: why this isn't worth pursuing right now

3. Present findings to the user. This is a conversation, not a document.

## Rules

- Be honest. If the idea has a fatal flaw, say so clearly and explain why.
- Don't default to "Go" — most ideas need pivoting.
- Keep it concise. This is a 10-minute analysis, not a business plan.
